DoubleZero TPU vs public Internet

For every eligible Solana leader run, this benchmark submitted one transaction through DoubleZero IBRL and one through the public Internet. Both arms ran from the same Frankfurt host, used the same relay binary, transaction shape, recent blockhash, slot trigger, and leader TPU endpoint.

Main PoH result: among 200 same-slot pairs with complete entry history, DoubleZero was recorded in an earlier PoH tick interval 91 times, both transactions were in the same interval 105 times, and public Internet was earlier 4 times. The effect was concentrated in distant leaders, especially one validator in Beauharnois, Canada.

What the PoH measure means

A Solana block contains transaction entries and periodic Proof of History tick entries. For each landed transaction, the analysis counts how many tick entries occurred earlier in that slot. A lower count means the transaction was recorded in an earlier PoH interval of the produced block.

This is block-placement evidence, not a packet-arrival timestamp from the leader TPU. Network transit, leader scheduling, queueing, and block packing can all influence placement. Only pairs landed in the same slot were compared, and a pair was excluded if its entry sequence was incomplete.

PoH tick-delta percentiles

Tick delta is the DoubleZero transaction's preceding-tick count minus the public transaction's count. A negative value favors DoubleZero; for example, -3 means the DoubleZero transaction was recorded three PoH intervals earlier in the same slot.

Does improvement match distance?

The observed pattern is consistent with that hypothesis: nearby European leaders were usually in the same PoH interval, while Beauharnois and Singapore were usually earlier through DoubleZero. Processed observation latency also favored DoubleZero by a median 6.683 ms in Beauharnois, while the larger European city cohorts were effectively tied.

It is not yet a general distance curve. The Beauharnois cohort comes from one validator observed across repeated leader runs and contributes 73 of the 90 distant pairs. Several other distant cities have too few pairs. The next defensible analysis is per-validator first, then distance or measured RTT across more distinct validators and more epochs. Repeated runs from one validator must not be treated as independent validator samples.

Methodology

Matched causal unit

One distinct transaction per arm from the same gRPC slot signal, current leader run, and recent blockhash. Payer-to-arm assignment rotated between groups.

Route isolation

The DoubleZero arm used normal Frankfurt routing through doublezero0. A temporary dedicated UID forced the public arm through bond0. Both relays used the same immutable binary.

Eligible leaders

Transactions were sent only when the saved leader snapshot reported networkPath.class == "doublezero" and verified == true. This is sender-specific TPU routing, not DoubleZero Edge shred publication.

Transaction shape

Both arms used TPU QUIC only, one attempt, a 660 CU limit, zero priority fee, and no route tip. All 492 submissions were accepted.

Observation clock

Signatures were matched against RPCEdge deshred and processed streams in Frankfurt. First observation includes leader admission, block production, propagation, and local observation.

PoH derivation

Processed transaction indexes were joined after the run to the immutable contiguous Yellowstone entry sequence. The sending and collection path was unchanged.
